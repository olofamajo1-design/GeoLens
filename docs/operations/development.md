# Local development and CI

Use a feature branch and submit changes through a pull request. The CI workflow runs on pull requests and pushes to main. It installs from the lockfile and runs the same `npm run check` command used locally.

The app binds to port 5173 in development and port 4173 in local preview. The built Worker smoke test uses port 4174. Free those ports before running the corresponding command. In a remote workbench, forward port 5173 or 4173 and open the forwarded URL.

In a sandbox with an unwritable home directory, run these commands from the repository root to redirect tool state to ignored directories:

```sh
export npm_config_cache="$PWD/.wrangler/npm-cache"
export XDG_CONFIG_HOME="$PWD/.wrangler/config"
export WRANGLER_SEND_METRICS=false
npm ci
npm run check
```

Schema validators are generated by npm lifecycle scripts before development, type checking, testing, and builds. Wrangler generates Worker binding types, and React Router generates route types. Keep generated files out of commits.

The fixture adapter needs no environment variables. Keep any future local credentials in ignored `.dev.vars` or `.env` files and use runtime secret bindings for deployed integrations when authorized. Never put credentials into client-side variables, logs, or commits.

The [Stage 5A newsroom](../architecture/newsroom-stage-5a.md) runs against disposable local Supabase with synthetic inputs and mock responses. Build the Worker with `npm run check` before running `npm run test:workflow`. The Workerd tests create the scoped fixture operator sessions and enable fixture mode only in the temporary local runtime.
